## Dependency notes

- 001 lands first because the existing line coverage is high but does not define the promised Perl semantics or test `src/browser.js`.
- 002 converts known semantic gaps from TODO cases into passing conformance cases.
- 003 uses the browser harness established by 001 to cover failed and overlapping executions.
- 004 uses the shared fake-DOM helpers from 001 instead of adding a third incompatible fake.
- 005 follows 003 so the final lifecycle API is what gets exported and documented.
- 006 follows 002 because token/source spans touch every lexer and parser node and would otherwise conflict heavily.

## Findings covered

- Perl falsehood and boolean result representation: 002
- Non-atomic reruns and listener leaks on failed startup: 003
- Missing `run`/`runScripts` package exports: 005
- Malformed numbers and incorrect string escapes/interpolation: 002
- Incorrect postfix operator precedence: 002
- Truncated DOM selectors containing `:`: 004
- Missing conformance and `browser.js` tests: 001 and 003
- Missing token locations, source-aware errors, and AST contracts: 006
- Repeated `textContent` concatenation on output-heavy paths: 004

## Product roadmap

Plan 007 starts the next product phase: **Perl 1.0 syntax. 2026 runtime.** It
keeps the existing Perl 1 Web Profile and low-level browser filehandles stable,
then adds a structured reactive UI layer without new language syntax or direct
DOM access. The plan is split into independently releasable milestones; M0 is
the next executable step.

## Findings considered and rejected

- Full TypeScript migration: deferred because it would change every source file without directly fixing a runtime defect. Plan 006 introduces checked JSDoc contracts first; TypeScript can be reconsidered after the grammar stabilizes.
- Parser-generator migration: rejected for now. Recursive descent plus Pratt parsing is appropriate for this grammar; correctness and diagnostics are the missing pieces, not parser generation.
